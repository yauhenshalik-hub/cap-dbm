# State-Based Database Migrations

Each schema change is a numbered **state**: a single Flyway migration applied in one transaction. `<N>` is derived automatically from the highest `V<n>` file in `db/migrations/`.

```sh
npx cap-dbm init    # first state only — full schema
npm run capture               # re-baseline db/snapshots/schema.csn to the current CDS model
npx cap-dbm delta   # every state after — diff vs db/snapshots/schema.csn
npx cap-dbm check   # verify snapshot and migrations are aligned (also run in CI)
```

> `npm run capture`, `npm run delta` and `npm run db:initial` are CDS-specific scripts expected to
> exist in the consuming project's `package.json` — this tool shells out to them. See
> [README](../README.md#required-npm-scripts) for the expected definitions.

| Topic                        | Details                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Layout**                   | One file per state: `db/migrations/V<N>__migration.sql`. DDL first, DML after, all in one transaction.                                                                                                                                                                                                                                               |
| **DDL**                      | Generated. Init flow (`npm run db:initial`) emits the full schema; delta flow (`npm run delta`) emits only the changes from state `N-1` to `N`.                                                                                                                                                                                                      |
| **DML**                      | A placeholder block at the bottom of the file. **You fill this in**: backfills for new non-nullable columns, one-off corrections. Keep it idempotent (`ON CONFLICT DO NOTHING`). Code-list rows are _not_ seeded here — load them from a data file after the migration if you need that.                                                          |
| **Workflow**                 | 1. Edit `.cds` → 2. `npx cap-dbm delta` → 3. review the SQL, add DML if needed → 4. commit + PR                                                                                                                                                                                                                                            |
| **`npm run capture`**        | Overwrites `db/snapshots/schema.csn` with the current CDS model. `cap-dbm delta` diffs against that file, so capture defines what "the previous state" is. To regenerate a delta: delete the bad `V<N>__migration.sql`, `git checkout db/snapshots/schema.csn`, then re-run `cap-dbm delta`. Both state commands call it automatically at the end. |
| **Commit together**          | The `.cds` change, `V<N>__migration.sql`, and `db/snapshots/schema.csn` (the baseline for the next delta — forgetting it breaks the next developer). `npx cap-dbm check` enforces this.                                                                                                                                                    |
| **Apply**                    | Flyway (or an equivalent runner) applies `V<N>__migration.sql` as part of your deployment pipeline. Locally: `psql -v ON_ERROR_STOP=1 --single-transaction -f db/migrations/V<N>__migration.sql`. Flyway wraps each migration in one transaction: all or nothing.                                                                                    |
| **`cds_model`**              | Not used. The delta is computed from the committed `db/snapshots/schema.csn` via `--delta-from`, never from a table in the database. Nothing writes `cds_model` and the app role should not have privilege to create it anyway.                                                                                                                     |
| **Lossy changes**            | The delta command warns on `DROP` / narrowing type changes. Never ship those as one state — use the expand → migrate → switch → contract cycle in [Schema Migration](schema-migration.md).                                                                                                                                                          |
| **Non-model objects**        | Objects not in the CDS model are never generated and must be added by hand to a migration. Applied migrations are frozen by checksum, so add new ones in a **new** migration. Prefer CDS-native constructs (e.g. `@assert.unique` on a `stored` column) where possible.                                                                             |
| **Scratch files**            | `initial.sql` and `delta.sql` are gitignored root output; the commands fold them into `V<N>__migration.sql`.                                                                                                                                                                                                                                          |
| **Commands**                 | `cap-dbm init`, `cap-dbm delta`, `cap-dbm check` — see [bin/cli.js](../bin/cli.js) and [scripts/](../scripts).                                                                                                                                                                                                          |
| **`No schema changes`**      | Your CDS edits produce no DDL, or `db/snapshots/schema.csn` is already current.                                                                                                                                                                                                                                                                      |
| **`CSN snapshot not found`** | `git checkout db/snapshots/schema.csn`, or `npx cap-dbm init` if this is the very first state.                                                                                                                                                                                                                                              |
| **`V<N> already exists`**    | Delete the bad run, or rebase onto the latest base branch.                                                                                                                                                                                                                                                                                            |
